Introducción al Monitoreo de Logs con ELK

Bienvenidos a este tutorial sobre el stack ELK. Centralizar logs es fundamental en cualquier estrategia de Blue Team. Hoy veremos cómo configurar un pipeline básico para recolectar y visualizar eventos de seguridad.

El stack se compone de tres elementos principales:

  • Elasticsearch: El motor de búsqueda y base de datos donde se almacenan los logs.
  • Logstash: El pipeline que ingesta, procesa, filtra y transforma los logs antes de enviarlos a Elasticsearch.
  • Kibana: La interfaz web para visualizar, consultar y crear dashboards con los datos.

Ejemplo de Configuración (Logstash)

Un filtro básico en Logstash para procesar logs de Apache podría verse así. Usamos `grok` para parsear el formato `COMBINEDAPACHELOG` y `geoip` para enriquecer la IP de origen:


input {
  file {
    path => "/var/log/apache2/access.log"
    start_position => "beginning"
  }
}

filter {
  grok {
    match => { "message" => "%{COMBINEDAPACHELOG}" }
  }
  geoip {
    source => "clientip"
  }
}

output {
  elasticsearch {
    hosts => ["http://localhost:9200"]
    index => "apache-logs-%{+YYYY.MM.dd}"
  }
}

Como pueden ver, la potencia de `grok` nos permite parsear texto no estructurado en campos útiles para Elasticsearch. En un próximo post, veremos cómo crear visualizaciones en Kibana con estos datos.
